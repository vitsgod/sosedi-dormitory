# Соседи — сервис общежития № 4

Fullstack-проект для портфолио на **Next.js, TypeScript и PostgreSQL**. Публичная главная с объявлениями и три кабинета: жилец, мастер, администратор. Учебная демонстрация, не официальный сайт РОСБИОТЕХа.

**Для пользователей:** [руководство по работе с сайтом](docs/USER_GUIDE.md) — вход, стирка, обращения, кабинеты мастера и администратора, уведомления и выбор темы.

## Что работает

- Обновлённое оформление и раздел «Настройки»: светлая, тёмная и системная темы. Выбор сохраняется в браузере, доступен во всех кабинетах и применяется также на главной и страницах входа. Быстрый переключатель находится в шапке сайта.

- Заявка на регистрацию с подтверждением администратора, серверные сессии, роли и специальности мастеров.
- Пять стиральных машин: окно записи 24 часа, до трёх одновременно, произвольная длительность 15–180 минут с шагом 5 и 10 минут на выгрузку. По понедельникам и ежедневно 07:00–08:00 запись закрыта. Время московское.
- Защита от конкурентного бронирования: блокировка строки рабочего пространства внутри транзакции и exclusion constraint PostgreSQL на пересекающиеся активные интервалы.
- Подтверждение начала в течение 10 минут, автоматическое освобождение неиспользованной брони.
- Заявки сантехнику, электрику и слесарю. Общая очередь специальности, атомарное принятие одним мастером, выполнение без подтверждения жильцом.
- Приватные жалобы со статусами. Фото проходят проверку формата/размера, перекодируются в WebP, отдаются только после серверной проверки прав.
- Актуальные, запланированные и архивные объявления, закрепление важных.
- Внутренние уведомления и отдельный worker. Повторные запуски не дублируют события.
- Быстрый демовход. Для посетителя создаётся отдельное пространство с вымышленными данными. Переключение ролей сохраняет это пространство. Демо очищается через восемь дней.

## Посмотреть локально

Если проект уже подготовлен на этом компьютере, откройте **http://localhost:3000**. Для повторного запуска в PowerShell:

```powershell
.\run-local.ps1
```

На главной в разделе демоверсии нажмите «Я жилец», «Я мастер» или «Я администратор». Пароли для демовхода не нужны. Внутри кабинета есть «Сменить роль».

## Установка с нуля

Требуется Node.js 24, PostgreSQL 18 (или Docker) и pnpm 11.25.0. Версии зависимостей закреплены в `pnpm-lock.yaml`.

```powershell
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile --ignore-scripts
Copy-Item .env.example .env
```

Укажите `DATABASE_URL` своей **новой отдельной** базы и `APP_ORIGIN`, совпадающий с адресом браузера. Для доступа настоящего администратора задайте `ADMIN_EMAIL` и длинный `ADMIN_PASSWORD` до первой загрузки seed. Seed не меняет пароль существующего администратора.

```powershell
pnpm exec prisma generate
pnpm run db:migrate
pnpm run db:seed
pnpm run build
pnpm run start
```

Во втором терминале запустите `pnpm run worker`. В режиме разработки — `pnpm run dev` вместо build/start. Эквивалентные `npm run ...` команды работают при установленных зависимостях.

Публичный seed содержит только синтетические профили с запрещённым обычным входом. Управляемые демонстрационные жильцы доступны исключительно в изолированном демопространстве. Пользовательская регистрация всегда остаётся на подтверждении.

## Docker Compose

В `.env` задайте `DB_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `APP_ORIGIN=http://localhost:3000`. Пароль БД должен быть URL-safe либо закодирован для URL. Затем:

```sh
docker compose up --build -d
```

Compose запускает PostgreSQL, миграции/seed, web и worker. База и приватные фотографии сохраняются в именованных volumes. Порт web привязан к localhost; БД наружу не публикуется. Docker-конфигурация подготовлена, но в текущей Windows-среде не запускалась: Docker не установлен в PATH.

## Сценарий для работодателя

1. На главной откройте «Я жилец». Запишитесь на стирку, затем отмените запись.
2. Создайте заявку сантехнику. Убедитесь, что она появилась в списке.
3. Через «Сменить роль» зайдите мастером, возьмите свою заявку и завершите её.
4. Вернитесь жильцом: статус изменился, в уведомлениях появились события.
5. Зайдите администратором: подтвердите тестового Даниила, назначьте ему специальность мастера, обработайте жалобу, опубликуйте объявление. Изменения не затронут других посетителей.

## Проверки

```sh
pnpm run test:unit
pnpm run typecheck
pnpm run build
```

Для интеграционных тестов создайте отдельную базу **dormitory_test** и примените к ней миграции. Тесты проверяют имя базы и отказываются запускаться на обычной базе. В PowerShell:

```powershell
$env:DATABASE_URL='postgresql://USER:PASSWORD@localhost:5432/dormitory_test'
pnpm run db:migrate
pnpm run test:integration
Remove-Item Env:DATABASE_URL
```

На запущенном сайте `pnpm run test:http` проверяет реальные HTTP-маршруты, CSRF, сессии, роли, полный путь заявки и выход. Он создаёт отдельное временное демопространство, которое автоматически удаляет worker. Фактические результаты и пределы проверки — в `docs/verification.md`.

## Архитектура

- `src/app` — страницы и HTTP-маршруты Next.js.
- `src/features/laundry` — время работы, бронирование, конкурентные ограничения.
- `src/features/requests` — заявки мастерам и приватные жалобы.
- `src/features/notifications` и `src/worker.ts` — фоновые задания.
- `src/lib` — авторизация, аккаунты, БД, демопространства, безопасная выдача файлов.
- `prisma` — схема, SQL-миграции с ограничениями PostgreSQL и seed.
- `src/components` — интерфейс, формы и иллюстрация общежития.

Сессии хранятся в БД в виде хеша случайного токена. Пароли хешируются scrypt с солью. Мутации проверяют Origin и права. Cookie HttpOnly/SameSite=Lax; при HTTPS включается Secure. Для общедоступного размещения обязателен точный `APP_ORIGIN` с HTTPS. Есть ограничения частоты входа, создания демопространств и загрузок.

## Ограничения демонстрации

- Состояние машинки отражает бронирования и действия людей, физического подключения к оборудованию нет.
- Напоминания видны только внутри сайта; уведомления вне браузера, Telegram и email не отправляются.
- Нет восстановления пароля, проверки почты и интеграции с университетскими системами; для демонстрации они не требуются.
- Контакты и адрес взяты из предоставленной карточки общежития в Яндекс Картах; объявления и все профили — вымышленные. Срок объявления не заменяет точную дату события.
- Иллюстрация здания нарисована в SVG специально для проекта и не претендует на точное изображение реального здания. Manrope распространяется по SIL Open Font License, лицензия в `public/fonts/OFL.txt`.
- Для публичной ссылки нужны Node.js-хостинг, PostgreSQL, постоянный volume для файлов и worker. Доступный Sites-хостинг рассчитан на Workers без прямых TCP-подключений; автоматическая публикация текущего Next.js/Prisma-стека через него не выполнялась. Не следует подменять серверную логику статической имитацией ради публикации.
