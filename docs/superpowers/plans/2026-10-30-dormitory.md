# Dormitory Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать демонстрационный fullstack-сервис общежития с тремя ролями, объявлениями, стиркой и обращениями.

**Architecture:** Единое Next.js приложение с PostgreSQL и серверными сессиями. Предметная логика выделена из HTTP-обработчиков; отдельный процесс выполняет периодические задания, данные остаются в общей БД.

**Tech Stack:** TypeScript, Next.js App Router, PostgreSQL, Prisma, Zod, Vitest, Docker Compose. Конкретные совместимые версии выбрать по текущей официальной документации до установки.

**Spec:** `docs/superpowers/specs/2026-10-30-dormitory-design.md`

## Global Constraints

- Время правил прачечной — Europe/Moscow, хранение моментов — UTC.
- Пять машинок; понедельник закрыт; уборка ежедневно 07:00–08:00.
- Начало брони в ближайшие 24 часа; длительность 15–180 минут с шагом 5; 10 минут на выгрузку.
- До трёх машинок одновременно на жильца; освобождение неподтверждённой записи через 10 минут.
- Жалобы приватны, без переписки; мастер закрывает заявку без подтверждения жильцом.
- Только уведомления внутри сайта; демонстрационные данные явно обозначены.
- Не заменять PostgreSQL браузерным хранилищем или имитацией API.

## Review Focus

- Границы полуночи, уборки и понедельника: весь интервал с выгрузкой должен быть допустим (Task 2).
- Параллельные запросы и повторные клики: БД сохраняет ограничения, ошибки возвращаются понятно (Tasks 2–3).
- Подмена идентификаторов пользователя или вложения: сервер отклоняет доступ к чужим данным (Tasks 1, 3).
- Перезапуск фонового процесса: задания повторяемы, уведомления не дублируются (Task 4).
- Общий демоаккаунт: посетитель не меняет его пароль, роль и доступность для остальных (Task 5).

## File Structure

- `src/app/` — публичные страницы, кабинеты, API маршруты; `src/components/` — общие элементы интерфейса.
- `src/lib/db.ts`, `auth.ts`, `permissions.ts`, `validation.ts` — инфраструктура и проверки.
- `src/features/{laundry,requests,complaints,announcements,notifications}/` — service.ts, schemas.ts и компоненты каждой функции.
- `src/lib/storage.ts` — приватные файлы; `src/worker.ts` — повторяемые фоновые операции.
- `prisma/schema.prisma`, `prisma/migrations/`, `prisma/seed.ts` — модель, ограничения, демонстрационные данные.
- `tests/unit/`, `tests/integration/` — правила и проверки с реальной БД.
- `compose.yaml`, `.env.example`, `README.md` — запуск приложения, PostgreSQL и worker.

## Самопроверка плана

Все разделы спецификации покрыты задачами 1–6. Предложенная изоляция демонстрационных сессий — техническая мера для сохранения общего демодоступа; роли и сценарии остаются теми же. Установка PostgreSQL и публикация зависят от доступных средств среды; отсутствие инструментов не считается успешной проверкой. Связанные доменные модули реализуются последовательно в текущей папке, отдельный worktree при пустом проекте не требуется.
